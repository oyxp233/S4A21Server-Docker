# A21 USERINFO1 客户端消费结构

本文以 A21 `NotiPacketTypeA21.USERINFO` 的 subtype 1 为主体，描述字段布局、消费条件、服务端投影和未确认语义。服务端成员名不直接作为客户端业务名称。

## 1. 证据基线

- 真实入口：`13E91E0` 读 `u8 subtype + u16 entryCount`，subtype 1 每条调用 `13E6370`。
- 字段宽度、顺序、条件和目标对象以当前 IDB/EXE 指令为准；反编译器命名、旧抓包和其他版本只作线索。

证据等级：

1. **已确认消费**：读宽、顺序和目标由指令或稳定调用链证明。
2. **已确认作用**：后续代码证明覆盖、清空、缩放、效果重建或 UI 使用。
3. **待确认语义**：知道字段边界和接收点，但缺少资源枚举或 UI 证据。

## 2. 完整消费结构（客户端预期）

### 2.1 外层和单条前缀

当前服务端每包写一条记录。单条 addition 起点为 body `+20`。

| body 偏移 | 类型 | 字段/来源 | 客户端消费 |
|---:|---|---|---|
| 0 | u8 | subtype=1 | 选择 subtype 1 分支 |
| 1 | u16 | entryCount=1 | 循环读取记录 |
| 3 | u32 | 成长胶囊进度 | 自身角色写全局缓存 `3A29CAC`；经验槽/tooltip 读取 |
| 7 | u16 | 未定名角色信息字段，当前固定 0 | 无符号扩展后覆盖角色记录 `+0x390`（内嵌角色信息 `+0x37C`）；业务语义与来源待确认 |
| 9 | u32 | 荣誉等级 | 更新角色荣誉缓存 |
| 13 | u32 | 荣誉经验 | 更新当前荣誉经验 |
| 17 | u8 | 光环状态 | 客户端按 s8 >0 取布尔，再 OR 角色记录 `+0x468` bit 3；0 不清除既有 bit，writer 规范化为 0/1 |
| 18 | u16 | characterId/userId | 查找已建立实体；找不到时不继续消费本条 addition |

#### 前缀短字段的已确认边界

- `13E6370` 读取 15B 前缀和角色 ID，并通过 `19E2EF0` 查找角色记录。完成 addition 读取后，`13E6729` 从前缀 `+4` 取无符号 16 位值，`13E6733 -> 13DEE20` 将其作为 32 位整数写入角色记录 `+0x390`。它不是可以省略的填充字节；0 会覆盖旧值。
- `27C6F20` 返回角色记录 `+0x14` 的内嵌角色信息，所以该字段也可表示为内嵌信息 `+0x37C`。角色记录与战斗 actor 是不同对象，不能把这两个偏移直接套到战斗 actor 上。
- subtype0 的 38B 固定头 `+2`（完整 body `+5`）经 `13E7E4A -> 13E7E54` 写入同一字段。当前 subtype0 writer 将整个固定头置零，因此只修改 subtype1 无法保证非零值在后续角色信息刷新后仍然保留。
- `13DEE20` 是多个类共用的短 setter。同地址调用和其他对象的 `+0x390` 访问不能单独证明业务语义；必须确认调用时的目标对象及后续数据流。
- 当前仅确认读取、存储和覆盖关系，尚未确认该角色字段的业务读取端、资源枚举或服务端 owner。保持 `WriteUInt16(0)`，不新建持久化字段或赋予猜测的玩法名称；接入业务值前必须补齐这些证据，并核对所有会覆盖它的 USERINFO 子类型。

### 2.2 addition 主体

下面按客户端读取顺序列出单条 addition。只有前 98B 的偏移固定；装备、技能、两类次数表和任务列表均由各自 count 决定长度。26 条副本次数是当前服务端默认列表，不是客户端规定的固定条数。

| addition 偏移 | 类型 | 字段/来源 | 客户端消费 |
|---:|---|---|---|
| 0 | u32 | CharacExp | 更新角色经验 |
| 4 | i32 | 属性 blob 长度=88 | 读取 88B 属性块 |
| 8 | 88B | 战斗属性 blob | 基础属性、抗性、附加属性和倍率 |
| 96 | u8 | ExEquipSlotStat | 写角色扩展装备槽状态 |
| 97 | u8 | 装备 count | 读取动态装备 entries |
| 98 | 可变 | 装备 entries | 按模板类型读取条件块、随机选项和扩展 blob |
| C=98+装备总字节数 | u32 | CloneTitleItemId | 独立于装备 entries 的克隆称号字段 |
| C+4 | u32 | NameTagItemId | 名签物品 |
| C+8 | u32 | NameTagExpireTime | 名签到期时间 |
| C+12 | u8 | SkillTreeIndex | 按 s8 使用；`FF` 为未指定页 |
| C+13 | u8+3N | 技能页 0 | count + `(u16 skillId,u8 level)` |
| 之后 | u8+3N | 技能页 1 | 始终存在，包括空页 |
| 之后 | u8 | EquippedCreatureLevel | 有宠物对象且非 0 时更新等级 |
| 之后 | u8+6N | 特殊副本次数 | `(u32 dungeonId,u8 ignored,u8 remaining)` |
| 之后 | u8,u8,u8 | 三个状态字节 | 写状态对象及两个布尔 map key |
| 之后 | u8+8N | 账号副本进入次数表 | count + `(u32 key,i16 limit,i16 used)`；写角色记录 `+0x530` 的 map，存储顺序 used/limit |
| 之后 | u8 | 角色任务碎片值 | 与 `NotiPacketTypeA21.CHARAC_QUEST_PIECE` 共用 setter，写 actor `+0x5FC4`，职业 9/10 用于条件效果 |
| 之后 | u32+4N | 特殊奖励任务 ID | 清旧集合、插入 ID、按 QST 资源重建效果 |
| 之后 | u8 | ManageLevel | 冒险团等级/效果 |
| 之后 | i32 | ManagePoint | 有符号点数，刷新冒险团 UI |
| 结束 | — | 无客户端读取 | 客户端预期在此结束 |

客户端在宠物等级后直接读取副本次数表，在冒险团点数后结束读取。writer 必须按此布局输出，不能插入未定义的字段或尾部数据。

设装备总字节数为 E、两页技能条数为 S0/S1、角色次数条数为 D、账号次数条数为 A、任务条数为 Q，则 addition 长度为 `129 + E + 3×(S0+S1) + 6×D + 8×A + 4×Q`。E=S0=S1=A=Q=0、D=26 时为 285B，单条完整 USERINFO1 body 为 305B。两页技能分别完整输出；装备或单页技能条数超过 u8 上限时拒绝构建，不能截断 count 后继续写入条目。

必须保留以下条件消费语义：

- `13E2540` 始终消费两页技能。自身角色分支仅跳过技能条目，不用 USERINFO1 覆盖当前技能树；其他角色分支先清旧技能，分别装载页 0/1，再按 s8 页索引选择，`FF` 时选择页 0。空页不是“复制上一页”的标志。
- 宠物等级字节始终读取；仅在等级非零且存在宠物对象时应用。后续自身角色的 `14D5310` 分支仅重建已有状态，不读取额外包体。
- `13E1D60` 的角色次数表每项读取 `u32 + u8 + u8`，中间字节不传给次数 setter。其后三字节依次写 actor `+0x5DF8`，以及将后两字节反转为两个布尔次数键的值；当前 writer 固定使用 `2/0/5`，并不投影 `DimFlag1..4`。
- 任务集合经 `1848550` 清空、`1863C60` 逐个插入 ID，之后由属性/效果重建路径消费 QST 资源；count=0 会清除旧集合。
- 三个状态字节、账号次数、任务碎片和冒险团各有独立读取位置，不能把固定尾数组中的 `0x6F` 当成不会被消费的分隔标记。

### 2.3 PvP 字段与账号副本次数的区分

`body +7` 的短字段与已确认的两个 PvP 等级字节不是同一字段：

| 字段 | 线上来源 | 客户端写入位置（以内嵌角色信息起点计） | 静态证据 |
|---|---|---|---|
| 未定名短字段 | subtype1 `body +7`，`u16` | `+0x37C`，普通 32 位整数 | `13E6729 -> 13DEE20`；角色记录偏移为 `+0x390` |
| PvP 等级字节（服务端名 `PvpGrade`） | subtype0 名字后的固定六字节区 `+3`，`u8` | `+0x2B8` 的安全整数 | `13E7340 -> 13E29E0`；`PVP_RECORD` 的 `1165CB0` 也更新这里 |
| PvP 分级字节（服务端名 `PvpRatingGrade`） | 同一六字节区 `+4`，`u8` | `+0x2C0` 的安全整数 | `13E7340 -> 13E2A90`；`PVP_RECORD` 的 `1165CB0` 也更新这里 |

`PVP_RECORD` 在前五个 32 位字段后读取上述两个 `u8`（通知 body `+20/+21`），再写入与 subtype0 相同的缓存。仅改变 subtype1 的 `body +7` 不会直接写入这两个等级位置；这能排除把该短字段直接命名为现有 PvP 等级或分级，但不能据此断言它与全部 PvP 业务绝无关联。

addition 后半段的八字节条目表属于账号副本进入次数。`13E1E40 -> 19E0F10` 与 `NotiPacketTypeA21.DUNGEON_ENTER_COUNT_INFO_INACCOUNT` 的处理器 `1162270 -> 19E0F10` 使用同一角色记录 map。`19E0F10` 接收完整 32 位次数键，将线上第二个、第一个有符号短值依次存为两个 32 位整数。当前代码的 `PvpResults` 只是误导性的历史名称，不能作为 PvP 统计语义的证据。

`19E0F40` 返回 used，`19E0F60` 返回 limit。`17566E0` 的显示路径输出 `(limit-used)/limit`，`25A7950` 的进入操作在 `limit-used <= 0` 时拒绝；因此线上顺序可确认是 limit/used。具体次数键如何映射到副本或入场组、重置周期和负值约定仍需资源证据，不能直接套用另一张角色次数表的副本 ID。

该表按键覆盖已有条目，不先清空整表。subtype1 的 count=0 会写入键 0、值 `(0,0)`，并不删除其他副本键；专用账号次数通知的 count=0 则不进入写入循环。

上述两个 PvP 字节来自 `characters.pvp_grade/pvp_rating_grade`，经 `SqliteCharacterRepository` 读取到 `CharacterRecord`；它们不属于 USERINFO1 的未定名短字段或账号次数表。

## 4. 动态装备 entry

服务端入口为 `ItemListProtocolWriter.WriteNoti2EquippedEntry`，客户端入口为 `1182850`。下表按实际读取顺序列出结构；成员名用于对应当前 writer，不替代资源枚举证据。

| 顺序 | 线上结构 | 客户端条件/当前 writer 对应 |
|---:|---|---|
| 1 | u8 slot、u32 itemId、u32 value、u8 attr、u16 durability、u32 sourceOrSeal | 固定 16B 头，顺序为槽位在前、模板 ID 在后 |
| 2 | 32 位长度 + 来源宝石 blob | slot=9、sourceOrSeal 非零且来源模板通过时装类型判定时读取 |
| 3 | u32、u8、u8、u16 | 附魔卡、附魔升级、增幅类型、增幅值，固定 8B |
| 4 | 两个 32 位长度前缀 blob | `1637740/1637790 -> 166EBC0` 判定当前模板类型 `+0x3C0` 为 0..11 时读取，分别对应 jewel/color |
| 5 | u32 | 当前模板类型为 25 时额外读取，当前 writer 对应宠物剩余时间 |
| 6 | u8 count + N×(u32 + 4×u8) | `11781D0`；当前模型 `ChronicleOptions`，每项 8B，不能记为固定块 |
| 7 | i32 | expire |
| 8 | u8 count + N×u32 | `1637A80`；徽章 ID 列表，当前 writer 最多投影两项 |
| 9 | u16 | `12612F0`；rune |
| 10 | u8 count + N×(u8,u8,u8)；条件尾见下文 | `1088BC0`；随机选项 |
| 11 | 3×u8 + u16 + 5×u8 | 固定 10B 实例尾，包含升级、解封等级、交易状态等；未知字节仍按未知语义处理 |
| 12 | 两个 32 位长度前缀 blob + u8 | entry 扩展块和末字节；勋章第二 blob 为 u16 guardian-gem compact keys，空孔必须保留 |

普通装备、时装、宠物和勋章扩展 blob 的长度使用字节数。随机选项 count=0 时不读取 state/index；count>0 才读取两个状态/索引字节，changedIndex!=FF 时再读 4B 变更项。不能无条件补齐这些条件字节。

时装/宠物条件来自客户端模板类型，不能只凭服务端 slot 或 `ItemKind` 名称推定另一类模板的布局。槽位模式与当前场景匹配时，`1182850` 末尾还会遍历 0..31，清理本条装备集合中没有出现的旧槽位；空装备列表不能视为“跳过装备刷新”。

装备循环后的克隆称号 u32 由 `1182850` 单独读取，随后 `13E6050` 固定读取名签的 8B（ID/到期值），再进入技能页 reader。它们不属于最后一件装备的扩展尾。

## 5. 当前服务端投影现状

### 5.1 成长胶囊

- 真源：账号表 `accounts.growth_capsule_exp`。
- 读取：`SqliteSubtype1Repository.Load` 使用角色的 `account_id` 和 `level`，调用 `GrowthCapsuleProgressRepository.LoadTotalExp`、`GrowthCapsuleDataProvider.Calculate/GetDisplayProgress`，写入 `UserInfoAdditionSnapshot.GrowthCapsuleExp`。
- 投影：登录、查看角色、USERINFO1 刷新、副本入口均调用同一前缀 writer，写入 body `+3`（addition 前缀 `+0`）。
- 规则：未达到服务端等级上限时发送 0；达到上限时发送按现有 PVF 上限裁剪后的账号进度。积累、领取、奖励和 EXP 通知由现有成长胶囊流程负责。
- 自测契约：`A21StartupProtocolSelfTest` 覆盖未满级=0、满级读取、清零后重载和 USERINFO1/EXP 一致性。

### 5.2 现有快照与组包边界

- 外层 subtype/count、荣誉前缀、光环标志、角色 ID 的写入入口稳定。
- 装备和 detail 通过现有 Inventory projection；builder 不查库、不写背包。
- 技能、宠物等级、副本次数、任务 ID、冒险团字段均由现有快照/服务组装，builder 不承担业务事务。

### 5.3 荣誉与冒险团

荣誉等级和经验来自账号荣誉投影，写入前缀 body `+9/+13`；冒险团等级和点数由 `AdventureGroupUserInfoSynchronizer` 写入 addition 尾部。USERINFO1 与 EXP 使用一致的荣誉快照；`13E6370 -> 13E2310` 更新荣誉缓存，`1178CD0 -> 8A6E80` 比较等级并决定升级提示。冒险团 `1847D10` 按等级重建效果，两项进度不能混用。

### 5.4 改名记录查询

`GET_USERINFO mode=5` 是角色改名记录查询，复用现有在线角色和同频道查看权限。响应使用 `NotiPacketTypeA21.CHARAC_NAME_CHANGE_LOG`；A21 `A72C80` 先清旧记录，再读取 u8 条目数并刷新窗口。当前角色业务没有持久化改名事件，返回单字节零条目，不能生成示例姓名、推测过往名称或将 GM 数据修正当作真实改名。后续正式改名功能须由改名事务同时保存历史后再接入查询。

## 6. 预留/未实现部分（客户端解析已确认）

以下项目已经知道客户端如何读取，但当前代码仍未完整实现或仍有结构差异，暂不声称完成：

| 项目 | 当前状态 | 影响 |
|---|---|---|
| 勋章首扩展 blob | 非零长度没有 payload 模型 | 可能导致动态 entry 读取不完整；需先补 payload 证据 |
| 账号副本进入次数表（代码名 `PvpResults`） | 格式和账号次数通知的共同 owner 已确认，当前 writer 固定 count=0 | 未投影真实账号次数；不能归类为 PvP 统计缺口 |
| 角色任务碎片值 | writer 固定写 `0x6F`，没有角色碎片真源投影 | 职业 9/10 的条件效果可能由固定值驱动，不能宣称已实现任务碎片进度 |
| 属性 17 项 | 客户端会应用，服务端只有默认值 | 不能声称完整战斗属性恢复 |
| 三个状态字节 | writer 固定 `2/0/5`，未使用快照中的 `DimFlag1..4` | 知道存储位置与布尔变换，不等于已接入对应业务状态 |
| 前缀 +4 u16 | 无符号读取及多个子类型覆盖同一角色字段已确认，固定写 0 | 业务读取端与 owner 未确认，不能接入猜测的非零值 |
| 属性 +83 f32 等 | 读宽/目标已知，业务名未定 | 仅能写“待确认”，不可擅自命名 |

这些项目需要逐项核对消费证据和业务真源，不应通过清零或填充数据掩盖。

## 7. 仅作推测的语义

以下名称没有足够资源/UI证据：

- 前缀 `+4` u16；
- 17 个附加属性的逐项枚举名；
- `+83` 浮点字段；
- 三个状态字节对应的具体玩法名；
- 账号副本次数键到副本/入场组的映射、周期和负值约定（limit/used 及其差值用途已确认）；
- 角色任务碎片值与任务、资源阈值和具体效果的完整对应关系；
- 装备动态 entry 中未知状态字节和首 blob payload。
