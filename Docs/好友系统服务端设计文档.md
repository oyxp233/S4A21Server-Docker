# 好友系统服务端设计文档（S4A21）

## 1. 业务边界

普通好友是单向关系：A 添加 B 直接建立 A→B，无需确认；删除只移除 A→B。普通好友与决斗好友协议独立。

## 2. 数据所有权

| 业务 | 服务端入口 | 数据真源 |
| --- | --- | --- |
| 普通好友 | `UnitedFriendSystem` / `UnitedFriendRepository` | 运行时 `Friends` 图；持久化 `united_friend_relations`，按角色名称区分大小写 |
| 永久黑名单 | `BlacklistHandler` / `BlacklistRepository` | `character_blacklist`，按操作者角色 ID → 目标角色 ID 保存 |
| 频道查询 | `UserChannelHandler` | 当前会话目录与已启用频道目录，无持久化 |

普通好友表由 schema v9 迁移创建，永久黑名单表由 schema v32 迁移创建；新库统一使用 `item_schema.sql`。协议名称和编号以 `Network/Core/PacketTypesA21.cs` 为准。本文 DSTR 均为 `[字节数:u32][GBK 字节]`。

增删请求通过角色 transition gate 执行；请求和排队响应绑定当前 session、角色 ID、UID、名称，发送前复验身份及相关关系。持久化成功后才更新内存和发送成功响应；发送失败不回滚已提交关系，重连从持久化状态恢复。

## 3. 普通好友增删

- 添加请求：`ADD_UNITED_SERVER_FRIEND [targetUID:u16][server:u8][name:DSTR]`。
- 删除请求：`DELETE_UNITED_SERVER_FRIEND [server:u8][name:DSTR]`。
- 成功 ACK：`[result:u8=1]`；失败 ACK：`[result:u8=0][error:u8]`。

server 只支持 1，名称为 1～255 GBK 字节；拒绝非法编码、空白名称、控制字符、截断和尾随数据。目标按精确名称查询，UID 仅作提示。允许跨频道和离线添加，排除自身、不存在及已删除角色。每个角色最多添加 64 人；重复添加幂等，重复删除失败。

好友写入在同一 Sync 锁内先提交仓储，再更新内存图；加载失败可重试。角色删除清理相关关系，改名在同一事务内更新双方名称键，并通知受影响的观察者。

添加成功后仅向操作者发送 ACK、完整列表及同频道目标的 USERINFO。删除成功后依次发送 ACK、subcmd=2 删除通知、subcmd=0 完整列表；删除最后一个好友时仍发送空列表。

## 4. 实时同步

### 4.1 完整列表

`UNITED_SERVER_FRIEND_INFO` 完整列表：

```text
[subcmd:i32=0][count:u32]
N × [server:u8][channel:u16][name:DSTR][level:u8][job:u32]
    [growType:u8][blacklist:u8=0][reserved:i32=0]
```

在线角色的等级、职业、转职取当前会话，离线角色取仓储。channel 同频道在线及离线均为 0，跨频道在线为实际频道号；同频道角色身份和状态由 USERINFO 提供。

subcmd=2 删除通知为 `[2:i32][count:u32][server:u8][name:DSTR]...`，用于删除节点并清除角色实体的好友标记。subcmd=0 会重建共享列表并清除永久黑名单节点，因此完整好友列表发送成功后必须恢复永久黑名单。登录与运行时刷新共用列表构建逻辑。

### 4.2 上下线、状态和等级

观察者按 `IsFriend(观察者, 变化角色)` 筛选。上线发送 `INOUT_UNITED_SERVER_FRIEND`，同频道随后补完整列表和 USERINFO；下线先发送上下线通知，再向同频道观察者发送 USER_LEAVE。状态变化仅向同频道观察者发送 USERINFO，升级和转职向所有观察者刷新列表。

上下线通知为 `[channel:u16][server:u8=1][name:DSTR][blacklist:u8]`，离线 channel=0；blacklist 按接收者的当前永久黑名单关系填写。场景实体仅在同频道投影。

### 4.3 频道跟随

好友、永久黑名单和临时黑名单菜单共用 `REQUEST_USER_CHANNEL`：

- 请求：`[server:u8=1][name:DSTR]`，名称 1～49 GBK 字节。
- 成功 ACK：`[1:u8][server:u8=1][name:DSTR][channelServer:u8=1][channel:u8]`。
- 失败 ACK：`[0:u8][error:u8]`；目标离线为 100，非法请求或频道不可用为 0。

服务端按精确名称查询当前在线会话，再由监听端口映射实际频道，支持代理端口；不依赖好友或黑名单关系，未知端口不回退默认频道。目标在房间内不等同于离线。发送前复验双方身份，目标下线、改名或会话替换时返回不可用，操作者身份失效时丢弃旧响应。

客户端先按 channelServer 筛选目录，再按 channel 查找频道；channelServer 必须匹配目录分组，channel 始终为实际频道号。同意移动后沿用既有换频道连接、认证、选角和准入流程。

原生客户端还限制可跟随的频道类型和区域：普通模式允许类型 0、3、22，或 `[sainthorn]`、`[zombie]`、`[deathtower]`、`[trade]`、`[crack]` 区域；特殊模式另有校验。当前 ch.100 符合条件，ch.10/ch.11 等类型 1 的普通推荐频道不符合。

## 5. 黑名单

### 5.1 永久关系与协议

永久黑名单与普通好友独立，上限 64 人。允许添加离线角色，排除自身、不存在及已删除角色。目标查询、容量检查和添加在同一即时事务内完成。改名不解除 ID 关系；软删除角色不参与屏蔽和列表，物理删除按外键级联清理。

角色名称按正式 GBK BLOB 存储查询，同时兼容 TEXT；列表按实际存储类型解码。

| 命令 | 请求 | 成功 ACK |
| --- | --- | --- |
| `REGISITER_TO_BLACKLIST` | `[name:DSTR]`，1～29 GBK 字节 | `[1:u8][name:DSTR]` |
| `DELETE_TO_BLACKLIST` | `[name:DSTR]`，1～29 GBK 字节 | `[1:u8][name:DSTR]` |
| `REQUEST_BLACKLIST` | 空 | `[1:u8][count:u8]`，随后逐条 `[name:DSTR][tm_year:u8][tm_mon:u8][tm_mday:u8]` |

失败 ACK 为 `[0:u8][error:u8]`。添加错误码：74 重复、76 目标不存在、78 名单已满，其余非法请求或存储失败返回通用失败。重复删除失败。日期从 UTC 加入时间转换为服务器本地日期，年减 1900、月从 0 开始；空名单返回零条数。

客户端列表按名称合并。`BlacklistProjection` 记录当前会话已发布的目标 ID 与名称，仅用于显示同步；屏蔽判断始终查询持久化 ID 关系。请求列表、登录完成及好友全量刷新后恢复永久名单，失效名字先发送删除 ACK，再发送当前列表。从旧名称删除时按该会话已显示的目标 ID 操作，避免名称复用误删。

### 5.2 屏蔽范围与客户端限制

永久黑名单在服务端限制双方新建 1vs1 会话、既有 1vs1 消息、组队/交易/决斗邀请及接受。新建会话被拒绝时仅向发起方返回 `CREATE_GROUP` 状态 77，不向目标发送开窗通知。普通聊天和公会聊天按接收者名单过滤。

玩家邮件在扣款、附件事务内检查收件人的黑名单，拦截返回 `Blacklisted`，不扣款、不投递；系统邮件及已提交邮件的幂等重试不受影响。解除永久关系后恢复通信。

黑名单页使用固定图标和灰色文字，不显示在线状态；灰色不代表离线。临时黑名单仅保存在客户端内存，不向服务端发送拉黑请求；它能过滤消息内容，但不能阻止原生 1vs1 开窗提示。
