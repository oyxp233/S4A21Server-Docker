# A21 普通金币拍卖行

## 功能

支持搜索、个人上架和竞拍列表、上架、撤单、竞价、一口价、按件购买及到期结算。物品和货款通过系统邮件交付。上架资格根据当前PVF的交易属性和背包中物品的实际状态判断，适用于普通可交易道具，不要求固定的PVF文件、物品ID或资源路径。

普通账号可上架5件，优惠账号30件；期限分别为24和48小时。成交手续费普通5%、优惠3%，按累计成交额计算并向下取整。每单押金10000金币，售完或到期退还，主动撤单不退。有人出价后不能撤单，同账号不能购买或竞拍自己的商品。同一角色加价只补差额，被超价后退还原出价。

固定价堆叠商品可按件购买；竞价商品整单成交。上架时将客户端报价统一为总价，并保存按件购买所需的单价。费用、期限和优惠状态在上架时确定，优惠到期不改变已有订单。

## 运行配置

设置`AUCTION_ENABLED=1`开启新交易。关闭入口时，已有订单仍正常恢复和到期结算。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `AUCTION_DATABASE_PATH` | `Data/auction.db` | 订单、托管物品、操作记录和交付索引 |
| `AUCTION_HISTORY_DATABASE_PATH` | 拍卖库同目录的`auction-history.db` | 成交历史 |

数据库由组合根初始化，分别使用`a21-auction-v1`和`a21-auction-history-v1`基线。升级沿用现有文件；备份时同时保存拍卖库、历史库和库存库。

## 开发接入

`ServerRuntimeBuilder.ConfigureAuctionRuntime`创建一个由所有频道共用的`AuctionRuntime`。`AuctionHandler`解析请求并调用应用服务，`AuctionListingEligibility`读取当前背包和PVF判定交易资格，`AuctionMarketApplication`组织交易，`AuctionMarketPlanner`计算订单变化与交付内容。

背包和金币沿用现有`InventoryLease`及库存事务接口。上架、购买和撤单保留完整99字节物品实例及相关详情，邮件领取使用这些数据恢复物品。上架来源包括Main、Avatar、Pet和GuildMedal随身背包，成功或失败后刷新对应背包。

一次交易依次记录拍卖库操作意图、库存库成交凭据和拍卖库最终状态。服务重启后根据凭据恢复未完成操作，重复请求复用原操作结果。到期结算复用`ClockService`。`AUCTION_RECOVERY_ONLY`构建用于关闭新交易入口并继续处理已有订单。

`IAuctionTradeHistoryReader`读取独立SQLite历史库。成交记录由已完成的订单操作生成，包括商品、数量、金额、手续费和买卖双方，支持按账号、角色及游标分页。历史投影可以从操作记录重建。

协议名称统一引用`PacketTypesA21.cs`。原生包体的读写位于`Network/Parsers/Auction`和`Network/Builders/Auction`；客户端列表数据用于显示，交付使用订单保存的完整物品数据。上架失败日志包含具体原因及来源背包、槽位、物品ID和数量。

## 验证与当前进度

设置实际使用的`PVF_ARCHIVE_PATH`后构建服务端，串行运行对应`--selftest-auction-*`；修改物品、金币或协议公共路径时运行`--selftest-all`。

原生交易历史界面尚未接入。限时实例、宠物本体和特殊详情的原生列表显示仍有未完成部分；普通道具的扩大支持需要继续补充客户端实测。这些是当前实现进度，不是对后续开发的设计限制。
